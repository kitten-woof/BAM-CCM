# BAM-CCM: версии 0.6 и 0.7

Исследовательский проект по восстановлению временных рядов методом **Convergent Cross Mapping (CCM)** и его модификациями. В репозитории находятся исходная версия BAM-CCM v0.6, отдельная экспериментальная версия v0.7, тесты и полный научный отчёт.

## Суть алгоритма

Классический CCM пытается восстановить значения ряда X по текущим и прошлым значениям ряда Y. Для этого он находит похожие состояния и использует значения ближайших соседей. При расчёте обычного евклидова расстояния все координаты задержки получают одинаковый вес, хотя одни могут быть существенно полезнее других.

**BAM-CCM v0.6** обучает преобразование пространства состояний: матрица L учитывает важность и связь координат, а дополнительные нелинейные функции позволяют изменять расстояния в разных областях пространства. Вместо усреднения ближайших соседей используется регрессия на основе **гауссовского процесса (GP)**. Доступны два режима: **BAM-MAP** (один оптимальный набор параметров с регуляризацией) и **BAM-Bayes** (усреднение по параметрам с помощью MCMC).

**BAM-CCM v0.7** дополнительно ограничивает чрезмерные локальные изменения преобразования с помощью **регуляризации якобиана**. При обучении используются начальные решения более простых GP-моделей. Цель изменений - сократить переобучение, особенно при небольшом числе наблюдений.

## Результаты исследования

В экспериментах сравнивались классический CCM, GP-Fixed, GP-ARD, GP-Full и варианты BAM на синтетических и реальных данных. Использовались независимые реализации, разные виды связи между рядами и разные размеры обучающей выборки.

- В большинстве тестов модели на основе GP точнее восстанавливали ряды, чем классический CCM. 
- BAM-CCM v0.6 показал меньшую ошибку восстановления (RMSE), чем классический simplex-CCM в 86,7% случаев (78 из 90 сравнений).
- В сравнении средних **RMSE** получилось **0,7907 у GP-ARD**, **0,8057 у BAM v0.6** и **0,8042 у BAM-Jac v0.7**. Меньшее значение означает более точное восстановление. То есть преимущество остается за более простым GP алгоритмом в сравнении с каждым BAM.
- v0.7 немного улучшила средний результат относительно v0.6, но устойчивого преимущества перед GP-ARD не показала.
- Высокая точность восстановления может наблюдаться и без непосредственной причинной связи, например из-за общего источника изменений или периодичности.

## Установка

Рекомендуется Python 3.11 или 3.12. Все команды ниже, если не оговорено иное, выполняются из корневой папки проекта.

На macOS / Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r original/requirements.txt
```

На Windows `.venv\Scripts\activate` (в PowerShell — `.venv\Scripts\Activate.ps1`), затем две команды с `pip`.

## BAM-CCM v0.6: запуск из терминала

**1. Проверить установку и исходные тесты:**

```bash
python original/bam_ccm.py --self-test
```

**2. Быстрый пробный запуск на синтетической логистической системе:**

```bash
python original/bam_ccm.py \
  --dataset synthetic --system logistic \
  --max-train 50 --map-maxiter 5 \
  --mcmc-warmup 10 --mcmc-steps 12 --no-curves
```

Этот режим годится только для проверки работоспособности: короткие MCMC-цепи не дают надёжных оценок.

**3. Пример запуска на финансовых данных из архива:**

```bash
python original/bam_ccm.py \
  --dataset qqq_volume --max-train 60 \
  --map-maxiter 10 --mcmc-warmup 20 \
  --mcmc-steps 20 --no-curves
```

**4. Сравнение на нескольких независимо сгенерированных траекториях:**

```bash
python original/bam_ccm.py \
  --benchmark --repeats 5 --noise 0.10 \
  --coupling 0.05 --max-train 65 \
  --map-maxiter 35 --mcmc-warmup 60 --mcmc-steps 100
```

Параметры: `--E` — размерность вектора задержек; `--tau` — шаг задержки; `--max-train` — размер обучающей библиотеки; `--n-centers` — число локальных центров; `--map-maxiter` — ограничение итераций MAP; `--mcmc-steps`, `--mcmc-chains`, `--mcmc-warmup` — настройки байесовского расчёта; `--seed` — генератор случайных чисел; `--output-tag` — суффикс результатов, чтобы различать запуски.

Результаты v0.6 записываются в `original/results/`, а новые синтетические CSV — в `original/data/synthetic/`. Список доступных параметров:

```bash
python original/bam_ccm.py --help
```

## BAM-CCM v0.7

В отличие от v0.6, v0.7 предоставлена как **класс `RefinedBAM`**

Создайте в корне проекта файл `example_v07.py`:

```python
import numpy as np
from modified.bam_ccm_v07 import RefinedBAM

rng = np.random.default_rng(42)
X = rng.normal(size=(85, 3))
y = np.sin(X[:, 0]) + 0.2 * X[:, 1] + 0.05 * rng.normal(size=85)

model = RefinedBAM(K=2, jacobian_weight=20.0, maxiter=65)
model.fit(X[:65], y[:65])
pred = model.predict(X[65:])
rmse = np.sqrt(np.mean((y[65:] - pred) ** 2))
print(f"RMSE: {rmse:.4f}")
print(model.diagnostics())
```

Запустите:

```bash
python example_v07.py
```

Здесь `X` — готовая матрица признаков, а пример показывает только работу API. Для настоящего CCM вместо случайной матрицы `X` нужно построить векторы временных задержек из одного ряда, а `y` взять из другого. Обучение и тест разделяются по времени; параметры нормировки вычисляются исключительно на обучающих данных.

Параметры `RefinedBAM`: `K` - количество локальных центров; `jacobian_weight` — сила ограничения локальных изменений (`0` означает отсутствие штрафа); `maxiter` — число итераций оптимизации. Метод `predict_ard(X_test)` даёт прогноз GP-ARD на тех же обучающих данных, а `diagnostics()` возвращает сведения о найденных параметрах и оптимизации.

## Повторение сравнения v0.6 и v0.7

Для отдельного сравнения GP-Fixed, GP-ARD, GP-Full, BAM-original, BAM-warm и BAM-Jac используйте:

```bash
# Предварительный выбор силы регуляризации
python experiments/run_metric_research.py --phase pilot

# Проверка выбранного значения на других независимых реализациях
python experiments/run_metric_research.py --phase confirm
```

Или оба этапа подряд:

```bash
python experiments/run_metric_research.py --phase all
```

Для отдельного запуска `confirm` нужен файл `experiments/results/metric_research/selection.json`, создаваемый на этапе `pilot`. Новые результаты сохраняются в `experiments/results/metric_research/`. Длительность зависит от компьютера и настроек, так как обучается несколько моделей на разных траекториях.

Другие проверки:

```bash
python -m pytest original/tests experiments/tests -q
python experiments/run_all.py --quick
```

`run_all.py --quick` запускает ряд дополнительных экспериментов и формирует таблицы и графики. Но это не заменяет сравнительный запуск v0.7 выше.
